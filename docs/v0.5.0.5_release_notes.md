## Lab 공급원

Lab의 기존 `BENCH_PRESS_E1RM`, `SQUAT_E1RM`, `DEADLIFT_E1RM` ID는
호환 키로 유지하지만 표시명과 값은 각 주의 마지막 persisted posterior
중앙값입니다. `StrengthAndMuscleMetricSeriesBuilder`의 Epley series와
`weight * (1 + reps / 30)` 계산은 제거했습니다.

Epley 계산은 이번 canonical performance UI/Lab 공급원 밖의 별도 책임인
strength index, fatigue intensity, program weight suggestion, exercise
analysis 및 legacy proxy experiment에는 남아 있습니다. 이들의 계산은 이번
작업에서 변경하지 않았습니다.

## 성장률 계약

`growthRatePercent = ((currentPosteriorMedian / previousPosteriorMedian) - 1) * 100`

현재 interval은 이전 중앙값 대비 low/high를 각각 변환한 설명용 범위이며,
두 시점 ratio의 정확한 posterior distribution이라고 주장하지 않습니다.

## 원인

기존 기록 백업은 workout과 분석 입력을 보존했지만 현재 training program
정의와 삭제한 built-in program 상태는 보존하지 않았습니다. 재설치 또는
복원 뒤 program의 local database ID가 바뀌고, 삭제한 seed program이 다시
생길 수 있었습니다.

## 변경

- `TrainingProgram`에 unique persistent stable key를 추가했습니다.
- Built-in은 seed `program_key`, 사용자/generated program은 UUID key를
  사용하며 수정·교체·이름 변경 때 identity를 보존합니다.
- Built-in 삭제 tombstone을 Room에 저장하고 seeding이 이를 존중합니다.
- 새 CSV export에 `program_snapshot`, `program`, `program_item`,
  `program_tombstone` row를 추가했습니다.
- Program item은 local ID 대신 program/exercise stable key로 이동합니다.
- 새 snapshot은 전체 program state를 transaction으로 정확히 교체하며,
  validation 또는 exercise remap 실패 시 전체 import를 rollback합니다.
- Marker 없는 legacy CSV는 기존 기록을 복원하면서 현재 program graph를
  전혀 변경하지 않습니다.
- Marker가 있는 빈 snapshot은 현재 program state가 비어 있었다는
  authoritative 상태로 처리합니다.
- 백업·복원 완료 문구에 program, item, tombstone 개수를 추가했습니다.

## 보존

Workout entry, confirmed/planned set, 이미 calendar에 적용한 계획,
historical analysis input과 기존 backup row semantics는 변경하지 않습니다.
Program 복원은 운동 기록을 삭제하거나 수정하지 않습니다. Destructive Room
migration과 display-name identity matching은 사용하지 않습니다.
