# v0.5.0.16 release notes

## Summary

v0.5.0.16 implements Phase 0 and Phase 1 of the metadata analysis contract.
It freezes the current behavior of OFI, program generation, muscle analysis,
badminton transfer, and connective-tissue capability by exact exercise
stableKey without switching any user-facing calculator to the new path.

## Baseline

- Source commit: `47f93eadaff64a49f6dc886a9319191c7388029c`
- Previous app version: `0.5.0.15 / 500015`
- Built-in exercise count: 224
- Room version: 26, unchanged
- Backup format: 9, unchanged
- Restore CSV schema: 8, unchanged

## Cause

Analysis meaning was spread across persisted metadata fields, fallback
parsers, calculators, and program policies. That made dependencies difficult
to audit and made a later typed migration unsafe without a behavior baseline.

## Changes

- Added a 102-field producer/consumer/disposition matrix for `Exercise` and
  `RuntimeExerciseMetadata`.
- Added a 292-location legacy parsing and inference inventory. Existing legacy
  readers remain unchanged and authoritative.
- Added typed, multi-row analysis relation models keyed only by exact
  `exerciseStableKey`.
- Added immutable contract asset `ANALYSIS_CONTRACT_BASELINE_V1`, containing
  9,781 relation rows for all 224 built-in exercises.
- Added explicit capability coverage for OFI, program generation, muscle load,
  badminton transfer, and the existing reviewed connective-tissue catalog.
- Added a conservative user-exercise projector. Missing relationships remain
  `INCOMPLETE`; names, stableKey fragments, and raw delimiters are not parsed.
- Added structured shadow parity, a deterministic public program-generation
  golden, duplicate/single-value validation, and a source architecture gate.

## Behavior

There is no intentional production behavior change. `DailyFatigueCalculator`,
`ProgramSkeletonGenerator`/`ProgramAutoBuilder`, muscle analysis, badminton
analysis, and all connective-tissue calculators remain the production
authorities. No user-facing service or UI reads the new contract repository.

The baseline marks existing behavior as `MIGRATED_CURRENT_BEHAVIOR`; it does
not claim new scientific evidence. Existing protocol versions, coefficients,
thresholds, labels, exercise identities, and backup semantics are unchanged.

## Storage and migration

Built-in relations are an immutable app asset. User relations are non-persisted
shadow projections of existing runtime metadata. Therefore this phase adds no
Room table, migration, exported schema, backup row, or restore rule. Zero user
rows are migrated. Unknown user relationships remain unresolved.

Rollback only removes the new package, assets, tests, and documents. No
database repair is required.
