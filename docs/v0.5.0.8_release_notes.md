# v0.5.0.8 Release Notes

## Purpose

v0.5.0.8 is a narrow legacy backup restore hotfix. It replaces four obsolete
equipment-disambiguation rules with reviewed direct mappings and allows the
deleted generic `원암 로우` Exercise definition to be skipped with a warning.

## Cause

Legacy backups containing generic Romanian deadlift or half-kneeling one-arm
press keys were rejected as ambiguous when equipment text was absent. The
deleted generic one-arm row definition was also treated as a blocking manual
resolution even though that exercise must remain absent from the current
catalog.

## Changes

- `ex_d2bb7946 / 루마니안 데드리프트`
  → `barbell_romanian_deadlift / 루마니안 바벨 데드리프트` (`DIRECT`).
- `ex_8380d7fe`, `ex_8e1b313e`, and `ex_66e8c8c2`
  → `half_kneeling_single_arm_dumbbell_press /
  하프 닐링 원암 덤벨 프레스` (`DIRECT`).
- Removed equipment disambiguation for those four legacy keys.
- Apply the direct stableKey resolution to legacy Exercise, WorkoutEntry, and
  TrainingProgramItem rows through the shared restore canonicalizer.
- `ex_e3487166 / 원암 로우` Exercise definitions are skipped with
  `LEGACY_DELETED_EXERCISE`; no active exercise is recreated.
- Updated both the generated asset and `canonicalize_exercise_catalog.py`.

## Preserved behavior

- Current exercise catalog, canonical metadata, tissue profiles, Room schema,
  backup schema, unrelated legacy aliases and normal runtime identity are
  unchanged.
- Deleted generic one-arm-row references in workout/program data are not
  guessed or silently discarded.

## Validation

- `LegacyExerciseImportMapperTest`: 5 tests passed.
- `BackupRestoreImportBehaviorTest`: 12 tests passed.
- Total targeted result: 17 tests, zero failures.
- Full unit tests, tissue tests, program-generation suites, prior generation,
  protocol-wide validation and APK build were intentionally not run.
