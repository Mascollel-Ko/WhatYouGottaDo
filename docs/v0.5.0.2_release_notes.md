- Baseline SHA: `03a331569fcee82ab9796a115060f7e6a2f07820`
- Baseline tag: `v0.5.0.1`
- Baseline app identity: `0.5.0.1 / 500001`

- v0.5.0.1의 metadata-constrained proxy performance model이 포함된 최신 `origin/main`에서 시작했습니다.

## 원인

v0.5.0.1 모델은 분석 화면을 열 때 mutable workout history를 다시 읽어 Epley 기반 관측과 posterior를 계산했습니다. 그 구조는 완료 세션과 조회를 구분하지 못하고, 원본 수정·삭제나 model policy 변경이 과거 그래프 의미를 바꿀 수 있으며, target enum·세 대상·고정 반복식에 묶여 있었습니다.

## 변경 내용

### 비선형 반복 곡선

- Nuzzo et al.의 public OSF 자료에서 reviewed general, bench-press, leg-press 표를 재현 가능한 generator로 변환했습니다.
- `q(1)=1`, finite `(0,1]`, monotone non-increasing, deterministic PCHIP/inversion과 1~12회 fail-closed 범위를 적용했습니다.
- exact bench/leg-press assignment와 borrowed/general fallback uncertainty를 stable-key registry로 분리했습니다.
- Epley는 새 likelihood에서 제거하고 기존 비교 series에만 남겼습니다.

### generic target와 중량 풀업

- 초기 target은 `strength.bench_press`, `strength.back_squat`, `strength.conventional_deadlift`, `strength.weighted_pull_up`입니다.
- direct anchor는 각각 `barbell_bench_press`, `barbell_back_squat`, `barbell_deadlift`, `ex_e41f4c2b`입니다.
- target/factor/load semantics는 string-key registry와 sparse loading row로 정의해 future target 추가가 Room migration이나 exhaustive enum을 요구하지 않게 했습니다.
- 중량 풀업은 당시 `bodyweight + added weight` 총부하를 state로 사용하며 체중 출처·당시 추가중량을 event history에 고정합니다.

### event-driven persistence

- Room `21 -> 22` migration으로 `strength_posterior_events`, `strength_posterior_history`, `strength_posterior_model_state`, `strength_curve_posteriors`, `strength_posterior_evidence`를 추가했습니다.
- record mutation transaction에서 canonical completion transition을 감지해 idempotent PENDING event를 만들고, posterior 처리는 background에서 수행한 뒤 한 transaction으로 commit합니다.
- partial deletion 뒤 confirmed set이 남으면 완료할 수 있지만 all-deleted session은 event가 아닙니다.
- 이후 세션, source edit/delete, curve calibration이나 app version은 과거 numeric history를 다시 쓰지 않습니다.
- one-time chronological bootstrap은 SQL migration 밖에서 실행되고 모든 event가 처리된 뒤에만 marker를 기록합니다.

### backup과 restore

- 기존 row-type CSV를 schema version `5`로 확장해 event, history, current state, curve posterior, compact evidence와 bootstrap manifest를 보존합니다.
- vector/covariance는 dimension, little-endian encoding과 SHA-256 checksum으로 직렬화합니다.
- exact duplicate는 skip하고 UUID/fingerprint 또는 immutable row conflict는 transaction 전체를 fail closed합니다.
- old backup은 그대로 import한 뒤 한 번만 chronological forward bootstrap합니다.

### 분석 UI

- Strength와 Lab은 raw workout replay 없이 persisted DAO state/history를 읽습니다.
- registry-driven 네 target, current posterior median/80% interval, direct/strong nRM/proxy count, curve calibration, model/curve version을 표시합니다.
- event detail은 저장된 prior, observation, posterior, interval change, predictive position, curve match와 중량 풀업 당시 체중 snapshot을 사용합니다.
- 기존 Epley chart는 `기존 공식 환산값`으로 표시하며 새 posterior에 사용되지 않는 역사 비교값이라고 설명합니다.
- Lab은 event ledger, fingerprint, version boundary, numerical diagnostics, backup/bootstrap provenance를 표시하고 Bayesian 시계열 Lab과 분리합니다.

## 남은 위험과 후속 과제

- squat, deadlift와 pull-up은 현재 general-resistance curve를 사용하므로 exercise-specific validation이 필요합니다.
- sparse proxy loading과 process variance는 product policy이며 실제 사용자 calibration이 필요합니다.
- persisted history는 filtered posterior snapshot이지 posterior draw archive가 아닙니다.
- strict BVAR/BLP bridge는 draw와 lineage를 보존하는 별도 승인 계약 없이는 만들지 않습니다.
- 연결된 emulator/device에서 `migrate21To22AddsPosteriorLedgerWithoutChangingWorkoutOrBootstrapping`를 실행하는 CI gate를 후속으로 권장합니다.
