# v0.5.0.33 canonical core and badminton objective cutover

## Baseline

- Started from latest `origin/main` at
  `532d2343cafd9e54924dc52350c6e108893b4b07` (`v0.5.0.32 / 500032`).
- The v0.5.0.32 canonical identity, movement-relation, and explicit badminton
  source boundaries are preserved.

## Cause

Strength analysis still exposed legacy functional core pseudo-buckets based on
general load, while badminton objective charts used duration, repetitions,
weight-sensitive dose, and an exercise-wide transfer interpretation. Those
paths could not represent the approved direct/indirect core semantics or
objective-specific transfer levels without competing scales.

## Canonical authority

- The user-approved 241-row core review is the sole CoreClass semantic source.
  Its SHA-256 is
  `3c819568012cd17726486e7f3e21cac972c95eec1736e8ab038e9edc1c3fa954`.
- `core_relations.csv` contains 272 facts: 241 class facts and 31 DIRECT target
  facts. Approved class and direct-target counts are unchanged.
- `badminton_objective_relations.csv` contains 278 explicit objective-level
  relations across 104 exercises and supports a distinct level per objective.
- The canonical objectives are ACCELERATION, DECELERATION, FOOTWORK,
  JUMP_LANDING, LUNGE_REACH, REACTION, CONDITIONING, ROTATION_GENERATION, and
  ANTI_ROTATION. ROTATION_POWER is compatibility input only.
- The rotation audit created 15 reviewed ROTATION_GENERATION relations. It
  created two and rejected two relations from the four approved core
  anti-rotation review candidates; final runtime ANTI_ROTATION authority has
  three explicit relations including preserved source authority.

## Calculation changes

CoreStimulus V1 uses confirmed sets, CoreClass coefficient, and a mild RPE
modifier. The coefficients are DIRECT 1.00, HIDDEN_HIGH 0.80,
HIDDEN_MODERATE 0.40, HIDDEN_LOW 0.15, and NONE 0.00. These are
research-informed ordinal product-policy priors, not physiological or EMG
effect-size estimates.

Badminton Objective Stimulus V2 uses confirmed sets, the same mild RPE
modifier, and objective-specific coefficients: DIRECT 1.00, SUPPORTIVE 0.60,
GENERAL 0.25, LOW 0.10, and NONE 0.00. Multi-objective stimulus intentionally
overlaps and is not divided by objective count.

Neither new calculator uses kilograms, effective kilograms, repetitions, or
seconds as a multiplier. Generic sport practice remains in its separate valid
practice-volume analysis and does not populate supporting-training objectives.

## UI changes

- Strength analysis now has a real cumulative stacked-area chart. INDIRECT is
  the lower area, DIRECT is stacked above it, and the top boundary is TOTAL.
- The card also shows cumulative total/direct/indirect values and indirect
  share. No-training dates carry the prior cumulative values.
- Legacy functional core pseudo-buckets no longer compete in the visible
  muscle-share UI; legitimate non-core anatomical analysis is preserved.
- The existing badminton analysis screen now always knows and displays all
  nine objectives, including zero values. ROTATION_GENERATION and
  ANTI_ROTATION use distinct fixed colors and localized labels.

## Historical replay and cutover

Raw confirmed workout records are replayed through the new calculators.
Compatible history-only stableKeys resolve through the existing canonical
identity path without rewriting stored identity. Production trend models no
longer contain `methodRaw`, and the new objective calculator does not call the
legacy metadata mapper or infer objectives from CoreClass/CoreDirectTarget.
There is no legacy derived fallback or old/new scale blending; zero is a valid
new result.

## Preserved behavior

Room, backup/restore, stableKeys, workout records, exercise CRUD, OFI,
readiness, fatigue, connective tissue, ProgramBuilder, e1RM, tonnage,
bodyweight effective load, duration-hold load, non-core muscle analysis, and
badminton practice volume are unchanged.

## Remaining limitations

- Objective levels migrated from an exercise-wide source retain provenance as
  inherited until a future objective-by-objective evidence review replaces
  them.
- GENERAL badminton relevance without an explicit objective remains outside
  the nine bars by design.
- User-created exercises without a canonical relation return zero rather than
  guessed core or badminton semantics.
