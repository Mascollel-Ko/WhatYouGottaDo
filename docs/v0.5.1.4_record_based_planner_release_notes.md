# v0.5.1.4 record-based planner implementation note

## User-visible behavior

- Added `기록 기반 알고리듬 프로그램 만들기` immediately below the existing automatic builder button.
- The new path uses persisted confirmed history through a fixed cutoff, asks only unresolved intent questions, and produces an editable 2-6 week plan with a concise rationale and confidence summary.
- Generation failure retains the current editor contents. Retry remains on the record-based path and never falls back to the legacy builder.

## Planning contract

- Observed behavior, explicit intent, adaptation gaps, candidate selection, strength style, badminton cost/context, and structured badminton objective stimulus are modeled separately.
- Exercise identity and fallback selection are canonical `stableKey` only. Generic badminton sessions do not count as structured objective stimulus.
- Every week, day, exercise, and set is materialized before the existing save/apply flow. Saved application remains exact and produces unconfirmed planned sets.
- Decision provenance records cutoff, window, horizon, intent and source, style and source, confidence, reasons, constraints, metadata authority, user answers, and prior-decision linkage.

## Compatibility and portability

- `ProgramGenerationService → ProgramSkeletonGenerator → ProgramAutoBuilder` and its existing button remain unchanged in behavior.
- Planner preferences and decision provenance are exported and restored as explicitly portable `app_meta`; seed, rebuild, report, and lineage metadata remain local.
- App version remains `0.5.1.4 / 501004`; this feature implementation does not bump it.
