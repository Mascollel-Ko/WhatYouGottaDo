# v0.5.1.4 record-based planner implementation note

## Planner v0.13.1 correction (2026-09-05; app version unchanged)

- Removes the generic-court-load three-day AUTO ceiling. Frequency uses demonstrated HIGH-qualified sustainable days, normal-week median, then recent training days, with explicit state ceilings and persisted provenance.
- Replaces global interruption cause authority with exact ISO-week annotations, up to three dated questions per generation and portable app_meta backup/restore. Legacy global cause remains readable but never labels all weeks.
- Global interruption frequency affects future core/optional placement only; timestamp freshness and contradictory confirmed interruptions can trigger re-questioning.
- Separates global readiness/unresolved severe-tissue restriction from local exercise/movement restrictions. Local restrictions preserve unrelated capacity and progression.
- HIGH sustainable capacity requires the same run's duration and performance coverage. Only qualified runs supply HIGH capacity. A confirmed single interruption can bridge adjacent normal segments without fake workload or performance evidence.
- Incomplete leading/current weeks do not count as full scheduling weeks. Actual performance/RPE, OFI/court/tissue history and exposure windows remain unchanged.
- Existing finite allocation, DIRECT/SUPPORTIVE behavior, multi-press support, top-nine/per-family anchor selection and proportional accessory allocation remain. Accessory over-allocation is not hidden by adding exercise-specific caps.
- Canonical protocol 3.3.1; no Room migration, Android version change or release tag.

## Planner v0.13.0 update (2026-09-05; app version unchanged)

- Uses longitudinal canonical OFI, matched movement performance, breadth and workload tolerance before finite scheduling. A high single-day OFI no longer repeatedly taxes demand, local anchors, horizon and capacity.
- Distinguishes likely interruptions/event patterns from observed recovery reduction. Repeated ambiguous low weeks trigger explicit cause/frequency questions; unknown means unknown, never an invented work trip or competition.
- Recent multi-week successful runs provide demonstrated sustainable workload evidence, not MRV, maximum safe or optimal workload. Strong evidence can release useful demand near that observed workload when availability and hard restrictions permit it.
- Frequent interruption preferences protect earlier core priorities instead of automatically lowering weekly units. DIRECT/SUPPORTIVE semantics, actual court physiology, tissue/OFI/posterior calculations and legacy ProgramAutoBuilder remain separate and unchanged.
- Adds backward-compatible assessment/context JSON to existing portable preferences/decisions. No Room migration, Android version change or release tag.
- Actual private-backup comparison and round-trip artifacts remain local; the committed Python fixtures contain synthetic observations only. Detailed evidence and limitations are in the existing implementation note and Codex worklog.

## Planner v0.12.0 update (2026-09-05; app version unchanged)

- Material resistance/badminton/performance needs share finite execution capacity. Actual prescriptions and rest determine placement; the fixed 4/5-item and duplicate high-court count caps are removed.
- More days/time can fund justified deferred work; spare availability alone does not create work. Normal AUTO badminton blocks respect the adaptation minimum; actual recovery bridges and explicit duration keep their separate meanings.
- Safe performance prescriptions use recent completed execution, exact canonical multi-week seed prescriptions, then existing reviewed rules. Rest-only metadata does not invent an exercise dose.
- Per the user's follow-up, explicit SUPPORTIVE assistance is now usable, including typed stability work. It remains distinct from DIRECT exposure in both evidence and saved provenance.
- Every generation first asks strength goal, badminton inclusion and free-weight willingness. The scrollable question dialog needs all valid answers; cancellation saves nothing and unknown intent does not silently create a short plan.
- Execution traces remain additive portable app_meta. No Room migration, app-version bump or release tag. Exposure thresholds, Objective V2 arithmetic, strength posterior, tissue arithmetic and legacy ProgramAutoBuilder are unchanged.

## User-visible behavior

- Added `기록 기반 알고리듬 프로그램 만들기` immediately below the existing automatic builder button.
- The new path uses persisted confirmed history through a fixed cutoff, asks only unresolved intent questions, and produces an editable 2-6 week plan with a concise rationale and confidence summary.
- Generation failure retains the current editor contents. Retry remains on the record-based path and never falls back to the legacy builder.

## Planning contract

- Observed behavior, explicit intent, adaptation gaps, candidate selection, strength style, badminton cost/context, and structured badminton objective stimulus are modeled separately.
- Exercise identity and fallback selection are canonical `stableKey` only. Generic badminton sessions do not count as structured objective stimulus.
- Every week, day, exercise, and set is materialized before the existing save/apply flow. Saved application remains exact and produces unconfirmed planned sets.
- Decision provenance records cutoff, window, horizon, intent and source, style and source, confidence, reasons, constraints, metadata authority, user answers, and prior-decision linkage.

## Compatibility and portability

- `ProgramGenerationService → ProgramSkeletonGenerator → ProgramAutoBuilder` and its existing button remain unchanged in behavior.
- Planner preferences and decision provenance are exported and restored as explicitly portable `app_meta`; seed, rebuild, report, and lineage metadata remain local.
- App version remains `0.5.1.4 / 501004`; this feature implementation does not bump it.

## v0.10 planner behavior update (2026-09-04)

- Upgraded the independent record-based path to a fixed 56-day current-block window, 28+28-day badminton objective comparison and weekly-equivalent court-load thresholds.
- Separated observed per-anchor style from next-block structure and dose treatment; added finite resistance-set reallocation and a separate timed-drill budget under the same session capacity.
- Replaced iterative questions with an all-at-once preflight followed by uninterrupted prepared generation. Record-based duration and weekly days now default to AUTO; explicit choices override them and the legacy ratio is ignored.
- Multi-day styles execute per anchor, use the strongest exposure in the latest observed week, and do not synthesize automatic progression across future weeks.
- Existing save/apply, canonical metadata, Objective V2, OFI, readiness, tissue RCV and exercise-local posterior authorities remain in place. No numerical authority outside the planner changed and no Room migration was required.
