# v0.5.0.10 Release Notes

## Purpose

v0.5.0.10 adds canonical date-level OFI context and exercise-name search to
the workout-record calendar.

## Changes

- Each visible historical calendar date now reuses
  `DailyFatigueResult.state.overallFatigueIndex` and continuously interpolates
  its existing cell color toward the Material `errorContainer` color.
- Rest days retain canonical residual fatigue where the existing calculator
  produces it. Missing and future OFI values do not invent a tint.
- Added live partial exercise-name search across both the current canonical
  exercise name and the historical workout-entry name snapshot.
- Matching dates require at least one confirmed set and use a 3.dp border that
  takes precedence over the existing 1.dp today border.
- Added contrast-safe calendar text selection for light, dark and dynamic
  Material themes.

## Behavior Preserved

OFI formulas, baselines, thresholds, labels, projected fatigue, calendar
navigation and actions, record mutations, and existing selected/record/plan
base colors are unchanged. Search does not highlight plan-only or
unconfirmed-only records.

## Validation

- Focused calendar presentation, search and OFI range tests passed.
- `:app:compileDebugKotlin` passed.
- Full `:app:testDebugUnitTest` passed: 1,075 tests and zero failures.
- `:app:assembleDebug` passed and produced a 46,676,079-byte APK with SHA-256
  `d6d9bbfa0df611722d34dacd12c1a32807056b627e81d51aecdd753b55e68aad`.
- Canonical protocol validation passed: 8 families and 32 protocols.
- Instrumentation tests were not run because `adb devices` reported no
  attached emulator or device.
