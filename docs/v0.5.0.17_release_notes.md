# v0.5.0.17 release notes

## Release identity

- Baseline: `7b5423208e22525ec765002591052b4b4b3bfb87` (`v0.5.0.16`)

## Cause

The Phase 0/1 design mixed current storage treatment with eventual migration destinations. In particular, `progressMetricType` was incorrectly described as a target canonical exercise relation even though it is a progress-analysis and prescription compatibility input. The repository also lacked a complete consumer-specific legacy mapping, compatibility inventory, and reviewed migration issue ledger.

## Changes

- Defined canonical exercise metadata as fixed exercise properties only.
- Documented exercise identity plus the seven movement/anatomy, program/equipment, OFI, muscle, badminton, connective-tissue, and provenance/review layers.
- Excluded workout-record input modes, measurement values, session selections, progress metrics, and computed outputs from target canonical metadata.
- Classified `progressMetricType` as `LEGACY_COMPATIBILITY_READONLY`, with target relation `NONE` and an explicit removal gate.
- Separated `currentDisposition` from `eventualReplacementStrategy` in the 102-row field-usage audit.
- Generated 1,254 consumer-specific legacy-to-target mapping rows.
- Generated 86 exact `progressMetricType` compatibility inventory rows covering 38 files and 68 enclosing symbols.
- Generated a curated 20-issue migration ledger for verified classification-manufacturing fallback paths while retaining the broader 499-row parsing/inference inventory.
- Added deterministic generation, mapping coverage, consumer completeness, heuristic issue-link, immutable baseline, and shadow-contract source gates.

## Provenance boundary

The current Phase 0/1 Kotlin model remains unchanged: it has three `AnalysisSourceStatus` values and one scalar confidence. `derivationMode`, `migrationFidelity`, `evidenceConfidence`, expanded human approval, and `REVIEWED_CANONICAL` are future v2.1 target concepts only. They require a separately approved Kotlin-model task.

Heuristic current behavior remains reproducible in immutable BASELINE_V1 and is linked to an issue. It remains `UNRESOLVED` in future REVIEWED_V1 until stableKey-level human review.
