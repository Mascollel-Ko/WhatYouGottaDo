# v0.5.0.7 Release Notes

## Release purpose

v0.5.0.7 is a validation-only correction for the v0.5.0.6 exercise
stableKey canonicalization release. It makes connective-tissue prior
generation deterministic across Windows CRLF and Linux LF checkouts.

The v0.5.0.6 tag remains immutable at `c825a4b941032b62c81b0860780fb5e6f0968efa`.
Its main and tag GitHub Actions runs exposed the platform-dependent input
checksum. v0.5.0.7 carries the correction instead of moving that published
tag.

## Cause

The generator normalized mapping and recovery authority files, but hashed the
scenario and prior-profile JSON files as raw text. Identical JSON content
therefore produced a different deterministic input checksum on Windows and
Linux. CI correctly rejected the generated registry as drifted.

## Changes

- Normalize scenario and prior-profile inputs before the deterministic input
  checksum is computed.
- Exercise the production checksum path with both LF and CRLF input bytes.
- Regenerate the canonical prior registry, app asset, manifest, and report.
- Update current protocol checksum references and runtime contract tests.
- Bump the app identity to `0.5.0.7 / 500007`.

## Behavior

No exercise identity, Room schema, backup format, tissue mapping, exposure
formula, recovery curve, prior value, PersonalBaseline, `w_perUnit`, program,
workout, strength, OFI, or UI behavior changed.

- Room schema `25`
