# v0.5.0.36 exercise-name semantic authority cleanup

## Baseline

- Started from `46ae449c039fb989309cc3de2ba4dc3c6dfdb6a8` (`v0.5.0.35`).
- Release identity: `0.5.0.36 / 500036`.
- Scope: production analysis semantic authority only. No Room schema, backup format, raw workout, ProgramBuilder authority, OFI/readiness formula, tissue calculation, CoreStimulus V1, or Badminton Objective Stimulus V2 change.

## Cause

Several analysis paths still treated mutable exercise names or name-like tokens as semantic evidence. Renaming an exercise could therefore change effective-load policy, hold policy, muscle attribution, major-lift identity, or record grouping. A disconnected legacy proxy-performance experiment also preserved old name-derived major-lift helpers beside the active persistent strength posterior.

## Changes

### Exact load authorities

- Added `BodyweightLoadProfileAuthority` with 19 reviewed exact stableKeys.
- Added `DurationHoldProfileAuthority` with `ex_a44ae2ca`, `ex_a8385c4a`, and `ex_f6d43398`.
- Removed display name, family, movement, equipment, mode, category, and substring inference from both calculators.
- Historical records resolve these policies directly from `WorkoutEntry.exerciseStableKey`, even without an `Exercise` row.
- Existing supported coefficients and RPE multipliers are numerically unchanged.

Bodyweight profiles:

- bodyweight plus added: `pull_up`, `ex_6466fe77`, `ex_6463edad`, `ex_deca2b61`, `ex_e1894690`, `ex_e41e8dcf`, `ex_e41f4c2b`, `ex_e4f911bb`
- inverted row 0.60: `ex_d9084b5e`, `ex_e159d15a`, `gymnastic_ring_inverted_row`, `suspension_trainer_inverted_row`
- push-up 0.65 / added 0.70: `ex_28902b13`, `ex_73b0b63f`, `ex_c4535de3`, `ex_debf6a8b`, `ex_fa2e73b3`
- pike push-up 0.70 / added 0.70: `ex_3caa236b`
- decline push-up 0.80 / added 0.70: `ex_fb67af37`

### Muscle and identity boundaries

- `MuscleLoadInputBuilder` now accepts only canonical primary/secondary muscle metadata. Exercise names and stableKey substrings cannot create muscle attribution.
- No missing canonical built-in muscle relation requiring a production metadata repair was found in the affected buckets.
- The old Korean-name substring heuristic incorrectly treated `ex_2a826c82` Hollow Body Hold as a row/back exercise. That accidental result is intentionally not preserved; CoreStimulus V1 remains its functional-core authority.
- `CommonStrengthMetrics` groups by stableKey rather than display name.
- Coach fatigue and RPE grouping use exact stableKey or deterministic record identity, while exercise names remain presentation labels only.

### Proxy boundary

- Deleted the production-unreachable `analysis/proxyperformance` experiment and its disconnected UI/tests.
- Preserved `analysis/strengthperformance`, `StrengthPerformanceRegistry`, reviewed proxy assets, posterior state/history, update service, backup codec, and current UI.
- Persistent strength mathematics and reviewed proxy coefficients are unchanged.

### Guard and audit

- Added architecture coverage preventing name-derived fields from returning to exact load/muscle/grouping authorities.
- Added rename-invariance, adversarial-name, missing-Exercise-row, exercise-search, ProgramBuilder 59-key authority, and persistent-strength preservation coverage.
- Added a classified exercise-name use audit and a separate `CALCULATOR_INTERNAL_METADATA_SEMANTIC_PARSING_DEBT` inventory.

## Behavior

- Exercise names remain visible, localizable, sortable, and searchable.
- Names no longer grant analytical semantics or recover record identity.
- Unknown exercises named Push Up, Pull Up, Side Plank, Bench Press, Row, or Squat fail closed without explicit authority.
- Canonical supported exercises retain their previous numerical results when their display name changes.
- ProgramBuilder candidate admission remains exactly 59 approved stableKeys.
