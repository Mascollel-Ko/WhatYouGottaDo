# v0.5.0.35 legacy authority cleanup

## Baseline

- Started from `origin/main` commit
  `8e5fcfd213fb7374647b4edcd91a999806492c67`, release
  `v0.5.0.34 / 500034`.
- This is a focused authority cleanup. Room, backup/restore, workout history,
  canonical metadata assets, connective tissue, OFI, readiness, strength
  posterior calculations, and public ProgramBuilder output are unchanged.

## Cause

- The retired badminton seven-axis score still had runtime, coverage, coach,
  state, and UI consumers beside the canonical nine-objective V2 model.
- Analysis Lab exposed anterior/lateral/rotation pseudo-core metrics with
  muscle-name fallback despite CoreStimulus V1 already being canonical.
- The disconnected advanced ProgramBuilder could admit candidates through
  metadata and name-derived classification without an exact rule-table key.

## Changes

### Badminton transfer authority

- Removed the legacy seven-axis calculator, mapper, score model, coverage
  analyzer, coach recommendation, state, and presentation paths.
- Preserved Badminton Objective Stimulus V2, its nine objectives, coefficients,
  reviewed relations, recent/weekly windows, and overlapping accounting.
- Preserved badminton practice duration/RPE volume. The retired share-based
  coverage model was not converted into the overlapping V2 objective scale.

### Core analysis authority

- Removed `MUSCLE_ANTERIOR_CORE_LOAD_*`, `MUSCLE_LATERAL_CORE_LOAD_*`, and
  `MUSCLE_ROTATION_CORE_LOAD_*` metrics and their name-based buckets.
- Added neutral Lab metrics for weekly total, direct, and indirect core
  stimulus. They delegate to the same `CoreStimulusWeeklySeries` aggregation
  as the canonical CoreStimulus V1 presentation.
- CoreClass coefficients, RPE modifier, raw-record replay, and weekly arithmetic
  are unchanged. A test-only historical oracle verifies parity.

### ProgramBuilder candidate authority

- Added `ProgramCandidateAuthority`, a typed read-only projection derived
  directly from `ProgramRuleTables`.
- The approved candidate set remains exactly 59 stableKeys. No candidate was
  added by this release.
- Applied exact-key admission before metadata classification in the advanced
  inventory, reservoir, and exercise-spec paths. Names, core tokens, roles,
  movement metadata, and similar strings cannot grant eligibility.
- Core-pattern rotation for admitted candidates uses exact approved stableKeys;
  it cannot create candidate authority.

## Public ProgramBuilder parity

The public path remains
`ProgramGenerationService -> ProgramSkeletonGenerator -> ProgramAutoBuilder`.
A deterministic golden compares 192 combinations:

- duration: 3, 4, 6, and 8 weeks;
- weekly training days: 3, 4, 5, and 7;
- session duration: 30, 45, and 60 minutes;
- badminton ratio: 0, 30, 50, and 70 percent.

All 192 scenarios preserve the pre-hardening periodization plan, week/day
placement, exercise stableKey sequence, order, role, slot, prescription, sets,
repetitions, and seconds. The matrix also proves that an unknown exercise with
Pallof/direct-core-like metadata cannot enter the result.
