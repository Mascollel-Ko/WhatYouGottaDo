# WhatYouGottaDo 0.5.0.23

## Summary

0.5.0.23 establishes the canonical Korean display-language authority for
metadata. It adds a researched terminology registry to the existing canonical
workbook, deterministically generates Korean/English resources, and routes
metadata UI and search through `MetadataDisplayCatalogue`.

The release also includes a startup-crash fix found while validating this
branch: Room table-rebuild migrations now keep child foreign keys pointed at
the final parent table names. The database schema remains 27.

## Display terminology

- Added workbook sheet `30_METADATA_DISPLAY_LABELS` with 1,819 rows:
  1,683 production pairs and 136 search-only compatibility pairs.
- Added deterministic `metadata_display_labels_ko.csv`, Korean XML, English
  XML, and a resource SHA-256 manifest.
- Added exact typed lookup for exercise category/mode/detail, muscles,
  equipment, body region, tissue, joint complex, OFI axis, roles, slots,
  recovery, progression, and the remaining production display namespaces.
- Search matches Korean primary/formal/common terms, English terms, and
  canonical codes while displaying one active-locale primary option.
- Preserved the product-owner primary label `e1RM` exactly.
- Removed ordinary UI stable-key exposure from the metadata editor.

## Validation

- Workbook schema, coverage, source/rationale, Latin allowlist, and exact
  `e1RM` checks are enforced by the validator.
- Exporter tests prove two exports are byte-identical and both XML catalogues
  have the same 1,819 canonical keys.
- Kotlin tests enumerate every production row and reject blank labels, raw
  snake-case labels, unknown fallbacks, and unapproved Latin text.
- Room migration regression tests cover final foreign-key targets and a cold
  launch over the previously failing database path.
- Final verification passed 1,149 unit tests, debug Android-test compilation,
  debug Kotlin compilation, debug APK assembly, and protocol validation for
  8 families and 33 protocols.

## Invariants

No canonical code, stableKey, relation, coefficient, formula, analysis result,
OFI/tissue/recovery behavior, ProgramBuilder policy, backup value, user record,
or Room schema version changed. Generated display resources can be rolled back
together without rewriting persisted data.
