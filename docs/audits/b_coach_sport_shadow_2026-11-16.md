# B-Coach Sport Shadow — 2026-11-16

## Scope

This diagnostic is read-only. The current production recommendation, candidate ranking, approval fingerprints,
persistence, recovery policies, and training programs must remain unchanged. It evaluates only candidates already
generated and verified by the production selector, after load resolution and hard constraints. It does **not** run
the missing exercise-roster reinsertion search. A candidate not generated by the original search cannot win this
shadow comparison.

## Score

Reuses the production evaluator's structured SPORT objective dose for each non-peak week. If lower > 0 and the
dose and interval are finite, define deficit = max(0, lower-dose)/max(1,lower) and excess =
max(0,dose-upper)/max(1,upper), each bounded to [0,1]. Shadow score = 0.85*mean(deficit) +
0.15*mean(excess); smaller is better for **this limited sport objective coverage criterion**. It is
not a validated adaptation probability, and is not an overall program-quality score.

All valid candidates are evaluated with the same objective catalog, as-of cutoff, load resolver, and
recovery constraints. The full production loss and max estimated session duration remain visible separately.
No physical activity is considered completed merely because the program was proposed.

## UI contract

- The program approval dialog offers '스포츠 Shadow · 후보별 결과 비교'.
- Read-only full-screen screen presents candidate count, original-recommendation and shadow-lower-loss labels,
  scores, weekly set totals, sport objective coverage by name, selected sport exercises, whole-week
  exercise/sets diffs, and week/day-specific sets, reps, loads, expected RIR and rest.
- A pinned back/close action returns to the original review **without applying the shadow candidate**.
- After accepting the production candidate, the last generation's shadow remains viewable until the user
  edits the draft or starts a new generation.
- The list of eligible but absent sport-related exercises is explicitly labeled **not in evaluated pool**,
  never falsely described as a measured score rejection.
- Missing shadow evidence/errors are presented as missing, not silently converted to zero.

## Required validation

- Robolectric: 320dp with 1.3 font scale, 12-week navigation, long names, pinned close, no apply action.
- Run local `:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebug`,
  `:app:compileReleaseKotlin`, `:app:compileDebugAndroidTestKotlin` and check device touch behavior.
- Re-run A9 accept → reconcile → persistence tests on the final commit.

## Remaining work

The new scoring approach is experimental and currently only reranks existing feasible candidates. A real
counterfactual search that revisits the exercise roster after evaluating loads, RIR, time and recovery is a
separate feature and **must not be claimed as implemented**. New exercise selection is not authorized by this
shadow alone.
