# B-Coach Gate G — 실제 운동 성공 기록을 다음 주 스쿼트 계획에 연결

**작업일:** 2026-11-13  
**코드 위치:** `BCoachLinkedSquatNextWeek.kt`, `BCoachLinkedSquatNextWeekService.kt`  
**상태:** 사용자 승인형 시험 기능 / main 미반영 / 스쿼트 한정  
**수식:** `b_coach_gate_f_curve_e1rm_progression_2026-11-12.md`의 동일한 기존 e1RM 반복곡선 및 목표 RIR–e1RM 근접도 비교를 재사용한다. 새 훈련 효과 계수는 추가하지 않는다.

## 실제 사용 흐름

1. **계획 생성**에서 사용자가 최소 원판 크기(한쪽 0.75 kg이면 바벨 총 증가 1.5 kg)를 입력한다.
2. B 프로그램의 `planningMetadataJson`에 `bCoachProgressionEquipmentSchema=linked-g-1` 및 `bCoachPlateOneSideKg`를 저장한다. 이후 프로필 변경이 기존 적용 프로그램의 계산에 임의 반영되지 않게 한다.
3. 생성된 프로그램을 **기록 달력에 적용**한다. 기존 `ProgramApplication`, `ProgramWorkoutLink`, `ProgramPrescriptionSet` 관계를 반드시 사용한다.
4. 1주차 스쿼트의 **모든 예정 세트가 실제 완료**되었고 중량·반복 목표를 달성했는지 확인한다. RPE와 기존 근력 곡선을 사용할 준비가 되어야 한다.
5. 같은 적용 프로그램·같은 진행 트랙·같은 요일의 **직전 주차**만 2주차의 근거가 된다. 일반적인 '같은 날짜' 또는 '같은 운동명'은 연결 근거가 아니다.
6. 가장 최신 정식 e1RM 앵커의 세트 ID와 직전 프로그램 기록의 세트 ID가 **전부 일치**해야 한다. 그렇지 않으면 계산을 보류한다. 미래 기록과 지연된 근력 모델도 거절한다.
7. Gate F는 유지 / 중량 +한 단계 / 반복 +1 / 필요 시 세트 +1을 고정된 수식으로 평가해 하나의 잠정 후보를 뽑는다. **이 단계에서 중량 자체에 보상 점수는 없다.**
8. 다음 주 운동이 아직 전혀 시작되지 않았고 사용자의 수정 흔적도 없으면 **기록 화면**에 'B-Coach · 다음 주 스쿼트 후보(실험)' 카드가 나타난다.
9. 사용자가 **이번 주차 계획에 적용**을 누르면 새 증거를 원자적 트랜잭션 안에서 다시 읽고, 지문이 동일한 경우에만 **그 특정 미래 운동 세트**의 중량·반복·계획값을 수정한다. 변경 이력은 기존 `progression_suggestions`에 승인 상태로 남긴다. 완료된 실제 세트·다른 프로그램·원본 프로그램 템플릿은 손대지 않는다.
10. 운동을 날짜 밀기/이동한 경우에도 프로그램의 원래 주차 링크가 유지되는 동안 날짜의 선후관계와 실제 세트 ID를 다시 확인한다. 링크가 끊기거나 이전 기록이 더 이상 근거가 되지 않으면 계획을 변경하지 않는다.

## 중요한 제약과 예외

- **사용자 승인형**이지 기록 저장 직후 무음 자동 업데이트가 아니다. 현재 Gate F 평가 계수와 세트별 피로 예측이 검증되지 않아 자동 저장은 허용하지 않는다.
- **다른 근력운동**은 아직 이 Gate G의 자동 진행 대상이 아니다. 별도 운동마다 정상적인 e1RM·RPE/RIR 및 체중 관련 표현을 검증한 뒤 확대한다.
- **세트 수 변동**은 Gate F 후보 계산에 포함되지만 실제 미완료 세트 개수와 맞지 않으면 변경을 차단한다. 기존에 미리 배정된 미래 세트 수와 후보 세트 수가 같을 때에만 저장 가능하다. 임의로 세트를 추가/삭제하지 않는다.
- 사용자가 미래 주차의 중량·반복·세트 구성을 수정한 경우, 최초 `ProgramPrescriptionSet.original*`와 달라진 것을 감지하여 우선한다.
- 과거 프로그램이나 원판 크기 스냅샷이 없는 프로그램은 업데이트하지 않는다. **이 브랜치에서 새로 생성하고 적용한 B 프로그램**만 대상이다.
- 검증된 성공 세션 없이 유지/증량을 강제로 쓰지 않는다. 실제 목표를 미달한 경우에는 본 게이트가 처리하지 않으며, 기존 진행 기능의 추천·수동 수정은 그대로 둔다.
- RPE가 없는 경우 근거를 만들어 내지 않으며, 최신 근력 모델이 생성되어 있지 않으면 계산하지 않는다.
- 기록 화면의 일반 진행 기능과 동일한 행을 자동으로 동시에 갱신하지 않으며, 기존에 승인/수동 결정한 진행 의견이 있으면 B-Coach 적용을 차단한다.
- 최신 연동 모델이 기록 시간보다 뒤처진 경우 `CANONICAL_MODEL_NOT_READY` 등으로 중단한다. 이후 모델이 정리된 뒤 다시 살펴본다.

## 이전 3kg 원판 경고 보완

이전 Shadow에는 설정값과 무관하게 `CONFIGURED_3KG`라는 문구가 남는 오류가 있었다. 경고를 **실제 설정 중량 간격**으로 바꾼다. 과거 기록의 중량 간격(예: 2.5 kg)이 오늘 사용자가 확인한 원판 규격(한쪽 0.75 kg → 전체 1.5 kg)과 달라도, 과거에 다른 원판을 사용했을 수 있다. 설정이 명시적으로 입력·저장된 새 계획에서는 **현재 저장된 간격으로 후보를 비교**하되, 과거 기록 간격 차이를 진단 메시지로 남긴다. 이 확인은 전체 운동 성공 확률에 대한 보증이 아니다.

## CI와 테스트
