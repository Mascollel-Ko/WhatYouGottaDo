# B-Coach 통합 처방과 검토

이 변경은 #87 → #88 → #89 위에 적용한다. 시작 커밋은 `1f3171bceff2da8ed17524d02856e0577948a5a6`이다.

## 생성

1. `V22ProgramPlanningService`가 확정 기록과 장비 정보를 읽고, 블록별 기준안과 후보를 만든다. `BCoachConfirmedLiftModel`은 최근 56일 안의 가장 최근 동일 종목 기록에서 모든 세트가 확정됐는지 확인한다. 첫 세트의 중량을 해당 종목의 반복곡선 `q(반복 + RIR)`으로 나눈다. RPE별 RIR 분포에서 가중평균과 범위를 구해 최신 개인 모델이 없을 때 사용한다. 스쿼트·데드리프트·바벨 벤치·덤벨 벤치가 대상이다. 덤벨은 양손 합계 kg이며 덤벨 벤치의 능력치는 그 운동의 기록에서만 가져온다.
2. `BCoachV2LoadCandidateResolver`가 주차·세트별 목표 반복, RIR, 장비 단위, 후속 세트 보정과 휴식을 반영한다. 세트별 처방을 확정한 뒤 후보를 평가하므로 검토한 계획이 승인과 저장으로 이어진다. 구형 첫 세트 교체기는 회귀 비교용 테스트 소스로 옮겼다.
3. `BCoachV2GlobalSelector`는 제한된 후보 탐색에서 종목 조합, 세트 수, 반복, 요일, 주요 운동 순서와 분산을 평가한다. 보조운동 4세트의 4, 2+2, 2+1+1을 탐색할 수 있다. 전체 주간 용량을 보존하는 분산에서만 일반 보조운동의 1세트를 허용한다. 훈련일·시간·잠금 조건을 확인하고, 실제 표시 처방이 다른 후보를 최대 세 개 제시한다. 탐색 예산 때문에 전역 최적을 보장하지 않는다.
4. 스포츠 점수는 아홉 목표의 노출량을 구분한다. 관측 근거가 있는 목표에 부족률 0.85, 초과율 0.15를 반영해 다른 목표와 함께 평가한다. 근거 없는 목표량은 미확정으로 취급한다. 일반 배드민턴 활동은 회복 부담에 포함한다. 보조 훈련의 점수는 기술 향상의 측정값이 아니다.
5. 시간·거리 운동에 시간과 횟수가 모두 비어 있으면 완성 후보에서 제외한다. 같은 운동·세트 순번에 최근 56일 내 확정한 시간이 있으면 최근 수행일의 시간을 사용한다. 중량을 들고 이동하는 운동은 같은 시간에 실제로 든 중량이 일치할 때만 유지한다. 근거가 없는 보조운동은 훈련일을 유지하는 제외안과 장비에 맞는 대체안을 평가한다. 사용자 잠금이나 주 운동을 이 규칙으로 삭제하지 않는다.

## 기록 연결

새 프로그램에는 장비 단위와 통합 진행 방식이 저장된다. 완료 후 같은 프로그램 적용 이력과 연결 순서에서 다음 미시작 운동을 찾고, 각 세트를 같은 순번의 확정 세트와 비교한다. 기존 예정 중량과 장비 한 단계 위·아래에서 예상 RIR 오차 제곱과 RIR 1 미만에 대한 벌점의 기대값을 비교한다. 오차 개선이 0.05를 넘어야 변경한다. 후보 한 단계의 상한은 바벨 5%, 합산 덤벨 7%다. 장비 한 단계가 이 상한보다 크면 계획 중량에서 반복 한 회를 더하거나 줄인 후보와 유지를 비교한다. 미보정 중량에서 완료 불가능한 반복을 예측하면 자동 적용을 보류한다. 이 수치는 제품 정책 계수다. 마지막 세트의 자동 감량 조건은 아래와 같다.

4세트 이상인 주요·보조운동에서 마지막 실측 RPE가 9.5 이상이고 다음 마지막 세트의 목표 RPE가 8 이하면, 중량·반복을 조정해도 목표 반복을 끝내지 못하는 모델 시나리오의 확률 합을 구한다. 마지막 세트에서 0.75 이상이고 앞의 모든 세트에서 각각 0.10 이하여야 마지막 한 세트를 줄인다. RPE가 미지정된 계획은 진행 모델의 기본 목표인 8을 사용한다. 앵커 세트·사용자 수정·시작한 운동은 보호한다. 이 확률은 반복곡선과 RPE→RIR 가정 아래 계산한 모델 수치다.

제외된 예정 세트의 원본 처방과 결정 이유는 보존한다. 이후 같은 트랙에서 이미 승인된 4세트 세션은 다시 진행할 수 있다. 직전 기록이 없는 네 번째 세트에는 예정된 중량을 유지한다. 자동 조정은 원래 승인된 세트 수 안에서 이뤄진다.

직전 기록, 예상 반복, 장비 단위, 수정 여부를 검사하고, 같은 트랜잭션에서 지문을 재검사한 뒤 해당 세트만 갱신한다. 결정한 다음 세션을 실행하면 다시 그 다음 연결 운동을 평가한다. 생성 이후 남은 모든 주차를 매번 다시 최적화하지 않는다. 기존 스쿼트 연결 프로그램은 기존 호환 경로를 사용한다.

## 메타데이터

데드버그에 대한 #87의 의미 교정을 원본 워크북에 동기화했다. 팔로프 프레스 2종, 버드독, 할로우 바디 홀드, 터키시 겟업, 플랭크, 코펜하겐 플랭크, 사이드 플랭크는 안정화 운동이라는 이유만으로 풋워크·감속 훈련량에 들어가지 않는다. 16개 관계의 ID와 증거 출처를 보존하고 두 기술에 대한 인정 용량을 0으로 설정했다. 팔로프 프레스의 별도 항회전 관계는 유효하다. 원본 CSV와 워크북에서 공식 exporter로 재생성하고 전체 파일의 일치를 확인했다.

## 품질 비교의 해석

같은 운동 기록이라도 장비 반올림 후 기존 처방이 유지될 수 있다. 6회, RPE 7 기록(데드리프트 180 kg, 바벨 벤치 70 kg, 덤벨 벤치 합계 48 kg)에 대한 4주 고정 반복 비교에서는 두 모델 모두 첫 주에 각각 177.5/172.5/172.5, 67.5/65/65, 46/44/44 kg을 처방했다. 이 비교는 목표를 유지하는 경우를 확인하며 우월성을 입증하지 않는다. 6개 프로그램 생성 fixture와 저장·재열기·캘린더 적용 결과는 Gradle 실행 시 `app/build/reports/b-coach/`에 작성된다. 실제 장기간의 운동 수행 결과는 별도 검증이 필요하다.

동일한 시드·기록·요청으로 #89와 이 브랜치의 `BCoachProductionQualityHarnessTest`를 각각 실행했다. #89 체크아웃은 Kotlin 컴파일을 위해 후보 변수에 기존 생성 결과의 타입을 명시했다. 아래 숫자는 각 버전이 추천한 계획에서 읽은 값이다. 각 칸은 #89 → 통합판 순서다. 회복 부담은 엔진 내부의 추정 손실이고 운동 결과를 측정한 값은 없다.

## Android와 영속성 검증

API 37 에뮬레이터를 720×1440 px, 360 dpi(320×640 dp), 한국어, 글자 130%로 설정했다. 3버튼 모드에서 Android가 대화상자를 1440 px 높이로 측정하고 실제 창은 y=79~1332 px까지만 표시하는 문제를 재현했다. 호스트 창의 시스템 바·컷아웃을 제외한 크기로 후보 검토와 스포츠 비교 창을 제한한다. 기기 테스트는 추천안의 첫 주와 12주 처방, 대안 선택, 승인·취소와 스포츠 비교 닫기를 검사하고 화면을 앱 외부 파일 디렉터리의 `b-coach-review`에 캡처한다.

생성 사례는 Room 저장·재열기·캘린더 적용을 포함한다. 연결 진행 회귀 테스트는 네 리프트에 대해 확정 세트, 날짜 간격이 다른 다음 세션, 한 세션 뒤의 원본과 중복 적용 방지를 데이터베이스에서 검사한다. 에뮬레이터 결과와 장기 훈련 효과 평가는 구분한다. 마지막 세트의 피로가 집중된 사례에서는 4→3세트 조정, 원본 보존, 재시도와 이후 4세트 연결을 함께 검사한다.
