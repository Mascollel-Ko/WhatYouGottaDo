# B-Coach Gate I — 계획 탭의 '운동 간 연결'을 실제 중량 진행 기준으로 사용

작성일: 2026-11-13  
상태: 별도 실험 브랜치(미출시). 기존 Gate F e1RM 평가식은 변경하지 않음. 스쿼트에 대해서만 실제 변경 경로 구현.

## 요구와 확인된 원인

사용자가 계획 화면에서 운동 A와 운동 B를 하나의 세션으로 **연결**했다면, A 운동 완료 후 실제 중량·반복·RPE를 기준으로 B의 처방을 재평가해야 한다. B가 '다음 주 같은 요일'일 필요는 없다. 날짜 밀기, 다른 요일, 중간 주차 공백에도 연결 순서는 보존되어야 한다.

Gate H는 같은 적용 프로그램과 종목을 확인했지만 `weekNumber = source.weekNumber + 1` 및 `dayOfWeek == source.dayOfWeek`에 묶여 있었다. Gate G의 역방향 점검도 `weekNumber - 1`, 같은 요일, 그리고 REVIEW 트랙을 단순 추측해 합치는 우회 경로를 사용했다. 즉, 계획 화면에서 지정한 세션 연결이 정확히 평가 기준이 아니었다.

## 기존 앱의 권위 있는 연결 정보

- 계획 단계의 `ProgramProgressionItem`: `logicalItemId`, `trackId`, `linkMode` (`AUTO`, `EXISTING`, `SEPARATE`, `OFF`)
- 적용 단계의 `ProgramWorkoutLink`: `applicationId`, `sourceProgramStableKey`, `trackId`, `sequence` 및 원래 주차/요일 메타데이터
- 기존 `ProgramProgressionService.configure`는 직접 연결 시 원본 프로그램 및 같은 운동 stableKey의 트랙만 허용하며, 명시적으로 분리한 운동은 별도 트랙을 부여한다
- 달력 이동 시 `relocate`는 적용 프로그램의 링크를 보존한다
- **이미 적용한 프로그램의 링크는 당시 스냅샷**이다. 원본 계획에서 나중에 연결을 변경해도 이미 달력에 적용된 운동의 트랙을 뒤에서 바꾸지 않는다

그래서 Gate I에서는 적용 기록의 **같은 `applicationId + sourceProgramStableKey + trackId`**만 연동 그룹으로 인정한다. 그 안에서 `sequence`가 현재보다 큰 것 중 가장 작은 값을 다음 연결 운동, 작은 것 중 가장 큰 값을 직전 연결 운동으로 정한다.

**주차와 요일은 대상을 찾는 키가 아니다.** 원래의 주차·요일은 화면 설명용으로만 남긴다. 날짜는 과거 계획 덮어쓰기를 막기 위한 안전 조건으로 검사한다.

### 연결 순서 예시

```
같은 적용 프로그램 / 하나의 스쿼트 진행 세션
1주차 월요일 135kg × 6 × 3 (RPE8 완료)
       ↓
3주차 목요일 스쿼트 (다음 연결 운동; 미완료)
       ↓
4주차 월요일 스쿼트 (그다음 연결 운동)
```

1주차 완료 후에는 **3주차 목요일**만 평가·변경한다. 4주차 계획을 곧바로 임의 변경하지 않는다. 3주차 운동이 완료되면 다시 4주차 계획을 평가한다. 중간에 연결하지 않은 다른 스쿼트가 있어도 같은 트랙이 아니면 이 연동 대상이 아니다.

## 실패 방지 규칙

- 해당 프로그램이 기록 달력에 적용되어 있어야 한다. 단순한 운동명·날짜 일치는 연결 증거가 아니다.
- 서로 다른 적용 ID, 세션 트랙 ID, 명시적으로 분리한 세션 또는 OFF/DIRECT 진행 모드는 절대로 합치지 않는다.
- 미래에서 가장 가까운 연결 운동이 이미 시작됐으면 그다음 연결 운동으로 **건너뛰지 않는다**.
- 같은 `sequence`에 연결 운동이 둘 이상이면 추측하지 않는다.
- 연결된 다른 종목 stableKey는 사용하지 않는다. 현재 Gate F 진행식은 스쿼트 한정이다.
- 직전 운동의 세트별 목표 성공·RPE·e1RM 증거를 계속 검증한다.
- 다음 연결 운동을 이미 수동 수정했거나 고정했으면 덮어쓰지 않는다.
- 연결된 운동이라도 **반복 횟수 목표가 다른 경우**에는 이전 운동의 반복 패턴을 임의로 복사하지 않는다. 다만 코치가 선정한 반복 증가 후보가 **이미 예정된 목표 반복 수와 정확히 일치**하면 그 목표를 유지하면서 진행할 수 있다. 예: '고중량 5회'와 '볼륨 8회'의 연결인데 선정 후보가 5~6회라면 강도 변환이 필요하므로 현재는 `LINKED_TARGET_REP_SCHEME_REVIEW`로 보류한다.
- 후보가 유지(HOLD)면 이전 실중량을 유지하는 것도 올바른 진행 결과이며, 빈 중량을 실제 중량으로 채울 수 있다.
- 실제 기록을 확인하면 기존 Gate H의 posterior refresh → Gate F 후보 평가 → 대상 보호 → 트랜잭션 기록 경로를 사용한다. 최초 주차 계산 및 타 운동 확대는 별도 게이트다.

## 변경 내역

1. `BCoachProgramLinkChain`: 다음/이전 연결 운동 선택을 단일 순수 로직으로 통일
2. `BCoachPostConfirmLinkResolver`: 동일 주차·요일 제약 제거, 적용 프로그램의 연결 세션과 다음 `sequence`만 확인
3. `BCoachLinkedSquatWeekPlanner`: 이전 주차/요일 근거 제거, 동일 세션의 직전 `sequence`로 증거를 검증. 임의 REVIEW 트랙 연결 금지
4. 결과 명칭 및 기록 화면 안내를 '다음 주'에서 '다음 연결 운동'으로 수정
5. 보존 규칙: 운동별 반복 패턴이 다르면 사용자 원본 처방 보호

## 검증

- 같은 트랙이라면 다른 요일, 여러 주 건너뛰어도 다음 연결 운동을 정확히 찾는가
- 다른 트랙/다른 적용 프로그램에 전달되지 않는가
- 같은 트랙의 여러 미래 운동 중 가장 가까운 대상 하나만 선택하는가
- 가장 가까운 미래 운동이 이미 시작됐으면 다음 것을 임의로 건너뛰지 않는가
- 특정 연결 운동의 반복 목표가 다르면 기존 처방을 덮어쓰지 않는가
- 후속 리그레션 테스트가 기존 원본 계획·수동 수정·완료 기록 보호를 유지하는가

**테스트를 통과해도 실기기 사용기록, UI, 개인별 최적 증량량의 적합성은 별도로 확인해야 한다.**
