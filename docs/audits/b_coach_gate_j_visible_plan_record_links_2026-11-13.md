# Gate J — 계획·기록 화면에서 명시적 운동 연결 표시 및 B 프로그램 AUTO 연결 보완

작성일: 2026-11-13. 별도 시험 브랜치, `main` 미수정.

## 이번에 해결하려는 재현 문제
B 프로그램은 처음에 킬로그램을 비워 놓고 생성한다. 기존의 `ProgressionTrackInference.sameTrack()`는 중량 미설정(`REVIEW`)인 운동을 AUTO로 연결하지 않는다. 저장 후 실제로는 각각 다른 `trackId`가 남아서 Gate I의 정확한 연결 검색은 `NO_NEXT_LINKED_EXERCISE`를 반환한다. 그래서 135kg×6회×3세트를 실제로 확인해도 다음 스쿼트가 보이지 않는다.

## 구현
1. `BCoachUncalibratedLinkPolicy`는 **원판 설정 스냅샷을 저장한 B 프로그램에서만** 중량을 아직 모르는 두 운동의 AUTO 연결을 허용한다. 동일 stableKey·세트 수·반복 패턴·스타일·변형·훈련 슬롯·강도·역할이어야 한다. 수동으로 분리한 `SEPARATE` 또는 다른 세션에 연결한 `EXISTING`, 연동 해제 `OFF`는 이 규칙보다 우선한다. 기본 전체 알고리즘 `ProgressionTrackInference.sameTrack`의 행동은 그대로 유지한다.
2. 저장 시 `ProgramProgressionService.author()`가 같은 목적의 B 자동 운동을 하나의 `trackId`로 묶는다. 달력 적용 시 `attach()`가 같은 적용 세션 ID와 순서를 복제한다.
3. 계획의 각 운동 카드에 `연결 세션 2/4 · 이전 1주차 1일 · 다음 3주차 4일` 또는 `단독 세션`을 별도 텍스트로 표시한다. 해당 행의 **진행/연결 설정**을 눌러 연결하거나 분리할 수 있다. 단독일 때도 진단 문구를 출력한다.
4. 기록 화면에는 `연결 세션 2/4 · 이전 11월 13일 → 현재 11월 20일 → 다음 12월 7일`처럼 **실제 적용된 기록 날짜**로 표시한다. `WorkoutDao.observeAllEntries()`를 통해 실제 기록 날짜를 관찰하므로 날짜 이동·밀기 후에도 연결 정보를 갱신한다. 원래 프로그램상 주차로 날짜를 추정하지 않는다.
5. 기존 Gate I가 `applicationId+sourceProgramStableKey+trackId+sequence` 순서로 다음 연결 운동을 찾는 방식을 유지한다. 계획-기록 화면 표시도 동일한 적용 세션 키를 사용한다.

## 변경하지 않은 것 및 보호 범위
- 스쿼트 Gate F 곡선 및 Gate I 자동 적용식은 변경하지 않았다. 연결이 제대로 저장되면 기존 스쿼트 연결 평가의 입력 조건이 충족될 수 있다. 사용자 기록·수동 수정·이미 시작한 대상은 계속 보호한다.
- **데드리프트는 이번 단계에서 새로운 e1RM 기반 자동 중량 상승 로직을 추가하지 않았다.** 데드리프트의 '다음 운동' 연결 관계는 시각적으로 표시하지만 그 연결 자체가 자동 증량을 보증하지는 않는다.
- 두 운동의 반복/세트 패턴이 다르면 무조건 합치지 않는다. 특히 heavy vs volume 구성이 다르면 현재는 자동 연결을 배제한다.
- 이전에 달력에 적용한 프로그램은 적용 당시의 연결 정보가 스냅샷으로 남는다. **새 연결 방식 테스트는 변경 후 새 B 프로그램을 저장하고, 그 프로그램을 기록 달력에 새로 적용**해야 한다.
- 날짜가 미래로 설정된 운동을 오늘 확인한 경우의 `SOURCE_IN_FUTURE` 보호는 그대로 유지한다. 테스트 데이터라면 실제 수행일과 계획 날짜를 분리해서 검증해야 한다.

## 통합 경로
```
B 생성 → 중량 미설정 AUTO 운동을 같은 목적일 때 trackId로 묶음
→ 계획 화면에서 이전/다음 연결 운동 표시
→ 기록 달력 적용 시 ProgramWorkoutLink에 같은 트랙/순서 보존
→ 기록 화면에서 실제 운동 날짜 기반 이전/다음 연결 표시
→ 세트 확인 후 Gate I의 기존 스쿼트 자동 조정 실행(조건 충족 시)
```

## 테스트
- `BCoachUncalibratedLinkPolicyTest`: B 메타데이터의 명시적 범위, 동일 스쿼트 연결, 다른 운동/반복/강도/슬롯/역할 배제.
- `ProgramLinkTimelineResolverTest`: 실제 이동한 날짜 사용, 분리 세션과 다른 적용 건 분리, 누락된 링크 날짜 추측 금지, 중복 순서 불허.
- Gate A~I focused 테스트와 Android 빌드/서명검증 재실행.

검증 중인 Shadow 선택식 자체의 일반화·다른 근력운동 자동 증량·첫 주 중량 자동 결정은 별도 작업이며 성공한 APK CI가 그 기능의 완성을 의미하지 않는다.
