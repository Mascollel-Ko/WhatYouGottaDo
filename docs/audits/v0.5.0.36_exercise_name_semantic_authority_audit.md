# v0.5.0.36 Exercise Name Semantic Authority Audit

Baseline: `46ae449c039fb989309cc3de2ba4dc3c6dfdb6a8`

Scope: production Kotlin under `analysis/` and `data/`, with caller tracing into search and ProgramBuilder authority tests.

## Classification

| Class | Reviewed use | Decision |
|---|---|---|
| A UI_DISPLAY | Analysis labels, fatigue cause labels, tissue provenance labels, persistent strength labels | Preserved. Names are output text only. |
| B SEARCH_OR_FILTER | Exercise list search, DAO exercise-name search, fatigue-source search | Preserved. Search behavior remains intentionally name-aware. |

| E PRODUCTION_SEMANTIC_INFERENCE_FROM_EXERCISE_NAME | Effective load, hold policy, muscle attribution, major-lift fallback, fatigue/RPE grouping, old proxy package | Removed from the audited analysis paths. |
| F OTHER_NON_NAME_STRING_LOGIC | Typed metadata token parsing, enum parsing, time-series keys, validation diagnostics | Preserved and inventoried separately where it still affects calculator semantics. |

## Removed Class E Paths

1. `BodyweightEffectiveLoadCalculator`: removed joined stableKey/display/family/movement/equipment/mode/category token matching. Exact stableKey profiles now select coefficients.
2. `DurationHoldLoadCalculator`: removed name and metadata token matching for plank policies. Exact stableKey profiles now select policies.
3. `MuscleLoadInputBuilder`: removed exercise-name and stableKey substring fallback attribution. Only explicit canonical primary/secondary muscle metadata contributes.
4. `StrengthAndMuscleMetricSeriesBuilder`: removed name-backed exercise resolution and delegates hold semantics to exact stableKey authority.
5. `CommonStrengthMetrics`: removed exercise-name grouping identity; records group by stableKey.
6. `CoachFatigueCauseAnalyzer`: removed `stableKey.ifBlank { exerciseName }`; unresolved records use deterministic record identity.
7. `RpeAutoregulationAnalyzer`: removed exercise-name grouping fallback; unresolved records use persistent record identity or deterministic entry identity.
8. Retired `analysis/proxyperformance`: removed production-unreachable name-derived major-lift helpers and the disconnected UI/model surface.

## Preserved Name Uses

- `AnalysisExerciseDisplayNameResolver` and summary models: display/localization only.
- `ExerciseSubcategoryMapper.matchesSearch`, Room search queries, and picker filters: search only.
- Backup/import/export rows: serialized display labels and diagnostics only.
- `CoachFatigueCauseAnalyzer` and `RpeAutoregulationAnalyzer`: selected-group label/message only, after grouping identity is already resolved without names.
- `MetadataReadinessReporter`: review diagnostics presentation; it does not assign exercise semantics.

## Canonical and Fail-Closed Results

- All 19 reviewed bodyweight stableKeys retain their previous intended coefficients.
- All three reviewed duration-hold stableKeys retain their previous intended policy and coefficient.
- Unmapped exercises named like push-ups, pull-ups, planks, rows, bench presses, or squats gain no analytical semantics.
- `ex_2a826c82` (Hollow Body Hold) no longer receives accidental row/back attribution from the Korean name substring that matched the old row heuristic. Its functional-core semantics remain owned by CoreStimulus V1.
- No built-in exercise requiring an explicit muscle metadata repair was found in the affected muscle buckets.
- Historical records with a governed stableKey resolve bodyweight/hold semantics even when the `Exercise` row is absent.
- ProgramBuilder admission remains the unchanged 59-key exact stableKey authority.

## Guard

`ExerciseNameSemanticAuthorityArchitectureTest` prevents presentation and heuristic fields from re-entering the exact load authorities, prevents name-based grouping fallback, keeps the retired proxy package absent, and confirms the active persistent `StrengthPerformanceRegistry` remains present.
