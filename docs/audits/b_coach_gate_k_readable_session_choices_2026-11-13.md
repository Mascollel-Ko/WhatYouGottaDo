# Gate K — 진행 세션 선택창에서 무엇과 연결됐는지 명확히 보여주기

2026-11-13 · 테스트 브랜치 전용. main 미수정.

## 사용자 재현
1~4주차 월요일의 스쿼트가 모두 `스쿼트 · 3×6 · 메인`이라는 똑같은 라디오 옵션으로 표시됐다. 어느 주차가 해당 세션의 구성원인지, 지금 선택한 `AUTO`가 실제 연결되었는지 알 방법이 없었다. 다른 trackId를 갖는 서로 다른 세션도 이름만 같으면 분간할 수 없었다.

## 선택창의 새 디자인
맨 위에 편집 중인 운동을 `2주차 월요일`처럼 표시한다. 그 아래 현재 화면에 실제 할당된 세션 구성원과 순서를
`1주차 월요일 → 2주차 월요일 → 3주차 월요일 → 4주차 월요일`로 보여준다. 각 기존 세션 선택 항목은 `스쿼트 · 1주차 월요일 시작 · 4개`라는 제목과 해당 세션의 **전체 순서**를 같이 제시한다. 같은 이름의 다른 세션도 첫 구성 주차와 전체 구성원으로 구분한다. 동일 주차·요일에 여러 운동이 있으면 `2번째 운동`을 붙인다.

선택의 실제 의미를 한국어로 직접 설명한다.

- **앱에 연결 판단 맡기기(AUTO)**: 운동 정체성·훈련 구성 등의 조건에 따라 앱이 연결한다. 이미 연결됐음을 의미하지 않는다. 실제 결과는 상단 현재 연결과 저장 후 상세 화면에서 확인한다.
- **기존 진행 세션에 직접 연결(EXISTING)**: 화면에 명시된 여러 주차의 세션과 현재 운동을 묶는다. 선택 당시 같은 세션을 고르면 사실상 기존 연결을 유지한다.
- **새 독립 세션 만들기(SEPARATE)**: 현재 운동을 명시적으로 다른 연결 그룹으로 떼어낸다. 다른 운동의 진행을 이어받지 않는다.
- **중량 자동 연동 끄기(OFF)**: 프로그램에는 남기되 중량 자동 연결을 해제한다.

선택 직후 `선택 예정` 설명도 별도로 보여줘, 저장 전후를 구분한다. 가장 긴 기존 세션은 여러 줄로 표시하여 `1주차 월요일`이 `1주차`만 보이고 생략되지 않도록 한다.

## 날짜의 의미
프로그램 생성/편집 단계에는 시작일이 확정되지 않으므로, 실제 `11월 13일` 등은 알 수 없다. **그 시점에는 주차·요일·순서를 명확히 표시한다.** 시작일로 달력에 적용한 후에는 기존 Gate J 기록 화면에서 실제 계획 날짜 및 이동/밀기로 바뀐 날짜를 보여준다. 날짜를 임의로 추정해서 잘못된 특정 월/일을 화면에 표시하지 않는다.

## 기존 B 자동 연결도 미리보기부터 일치시킨다
기존 Gate J는 B 프로그램을 DB에 저장할 때만 중량이 미정인 동일 운동·동일 반복 구성의 AUTO 세션을 합쳤다. 생성 직후 미리보기는 서로 다른 세션으로 남아 있어, 사용자가 `자동`을 눌렀을 때 무엇이 실제로 연결될지 몰랐다. Gate K는 동일한 보수적 정책을 B 미리보기 `reconcileProgression()`와 세션 설정에도 적용한다.

반복되는 화면 상태 갱신으로 ID가 계속 생성되거나 무한 재구성이 생기지 않도록, **이미 같은 세션에 연결되어 있으면 기존 ID를 유지**한다. 저장된 연결 및 명시적 EXISTING/SEPARATE/OFF는 변경하지 않는다. B 외의 기존 자동 분류는 그대로 유지한다.

## 테스트
- `ProgressionSessionLabelsTest`: 4주 모두 순서대로 표기, 동일 주차의 운동 순서, 달력 날짜의 임의 생성 방지.
- `ProgramProgressionDraftTest`: B 미리보기 4주 AUTO 연결, 여러 차례 재계산해도 ID가 동일, 수동 분리 보호, B 외 기존 동작 유지.
- `ProgramProgressionLayoutTest`: 좁은 320/360/411dp + 큰 글꼴 환경에서 메뉴가 보이고, 연결 대상 주차 전체를 실제로 확인할 수 있는지 테스트.
- Gate J의 실제 저장/달력 적용/기록 날짜 연결 회귀 테스트도 같이 실행. Android 코드 컴파일과 서명 디버그·성능 APK CI 확인.

## 이번 작업의 한계
세션을 보여주는 것과 실제 운동별 증량 계산은 별개의 기능이다. Gate I의 스쿼트 자동 진행 경로는 유지하지만 데드리프트 e1RM·RPE 자동 처방은 이 작업에 추가하지 않는다. 또한 이전에 달력에 적용한 운동 연결은 당시 스냅샷이어서 계획에서 연결을 새로 지정했다고 이미 적용된 기록의 연결이 조용히 변경되지는 않는다.
