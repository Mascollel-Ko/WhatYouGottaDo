# v0.5.0.34 analysis presentation and badminton authority corrections

## Baseline

- Started from `origin/main` commit
  `6e423e49a0062d6f9d687ad54a890724fde6c845`, release
  `v0.5.0.33 / 500033`.
- Implementation audit target: `6498ab7`.
- This release preserves the v0.5.0.33 CoreStimulus V1 and Badminton
  Objective Stimulus V2 calculators.

## Cause

- The badminton objective UI default sorted totals and selected only four
  objectives, reducing the visible canonical nine-objective authority before
  both charts were built.
- Selected zero-valued objectives were removed from stacked segments and the
  horizontally scrolling legend made the last canonical categories unclear.
- The strength core card displayed cumulative daily data even though the
  calculator already exposed authoritative daily DIRECT and INDIRECT values.
- Band and cable Pallof presses had explicit product-owner anti-rotation
  approval that was not represented in the generated badminton objective
  authority.

## Changes

### Badminton objective UI

- Fresh and reset state now selects all nine objectives in canonical order.
- A transient `v2-all-nine` state prefix resets historical raw top-four saved
  UI state once while preserving user subsets saved by the new build.
- Recent and weekly stacked chart models retain selected zero-valued segments.
  The two badminton objective charts use a wrapped multi-row legend so all nine
  fixed-color categories are visible on mobile layouts.
- The objective picker and manual subset behavior remain available.

### Weekly core presentation

- `CoreStimulusWeeklySeries` sums authoritative daily values by the existing
  Monday-Sunday temporal policy.
- Missing weeks are explicit zeroes with no carry-forward.
- The main chart remains a true stacked area: INDIRECT below DIRECT and TOTAL
  as the upper boundary. The footer reports the latest displayed week.
- A representative sequence renders as `7, 3, 5`, not cumulative
  `7, 10, 15`.

### Pallof reviewed authority

- Added deterministic decision source
  `docs/metadata_authority/badminton_objective_review_decisions_2026-08-14.csv`.
- `band_pallof_press` and `cable_pallof_press` now add
  `ANTI_ROTATION / SUPPORTIVE` under provenance
  `USER_APPROVED_BADMINTON_OBJECTIVE_2026_08_14`.
- No fake legacy evidence key was created. Empty evidence is accepted only for
  that exact user-approved provenance with PASS status and a nonblank reason.
- Existing Pallof `DECELERATION / SUPPORTIVE` and `FOOTWORK / SUPPORTIVE`
  relations remain. Generated objective rows changed exactly from 278 to 280.

## Preserved calculations and systems

- Recent 7 days still includes days 0 through 6.
- Recent 28 days still includes days 0 through 27 and overlaps the recent
  7-day period; its chart value remains `total / 28 * 7`.
- Badminton coefficients, mild RPE modifier, overlapping objective accounting,
  and no-kg/reps/seconds rule are unchanged.
- CoreClass coefficients, mild RPE modifier, sport-session exclusion,
  no-kg/reps/seconds rule, calculation version, and cumulative compatibility
  data are unchanged.
- Room, backup/restore, raw workout history, stableKeys, OFI, readiness,
  fatigue, connective tissue, ProgramBuilder, e1RM, tonnage, non-core muscle
  analysis, and badminton practice volume are unchanged.

## Copenhagen decision and remaining debt

- Copenhagen plank (`ex_a8385c4a`) still has only inherited
  `DECELERATION / SUPPORTIVE` and `FOOTWORK / SUPPORTIVE` relations.
- This release adds neither `ANTI_ROTATION` nor `LUNGE_REACH` to Copenhagen.
- Its inherited deceleration/footwork semantics were preserved rather than
  revalidated and remain a separate future semantic-review task.
