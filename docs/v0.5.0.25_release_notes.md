# v0.5.0.25 release notes

## Purpose

v0.5.0.25 separates current canonical exercise metadata from explicit user
overrides and makes full backup restore selectable and atomic when the target
already contains workout and exercise-list changes.

Baseline: `6e6f9fbedd1c121398afd3a92c9dd7217b6d4a6a` (0.5.0.24,
Room 28, backup format 11, restore schema 10).

## Cause

Persisted runtime metadata and old backup snapshots could previously look like
user authority simply because they differed from the current seed. Restore also
had no explicit choice for overlapping workout days or the projected active
exercise list, and database-local numeric references were not a sufficient
cross-install identity contract.

## Metadata ownership

- Current built-ins now resolve as current semantic seed plus explicit
  field-level override rows plus independent `isActive`, `archivedAt`, and
  `needsReview` state.
- Room 29 adds `exercise_metadata_user_overrides`; migration reconciliation is
  semantic-revision keyed and does not infer user intent from value difference.
- The editor writes only dirty override fields, preserves explicit empty, and
  reset removes explicit authority before rebuilding effective state.
- Semantic and display revisions use separate deterministic projections. The
  109-row field registry exports a CSV and Android asset contract plus revision
  manifest; localized labels are not persisted as canonical metadata.

## Safe selectable restore

- Backup format 12 and restore schema 11 declare
  `EXPLICIT_METADATA_USER_OVERRIDES_V1`, complete represented exercise user
  state, immutable workout source identities, and backup-scoped parent links.
- The UI asks exactly two new questions: replace or append overlapping workout
  days, then preserve or apply the backup active exercise list. Zero overlap
  skips the first question and internally uses append.
- No Room mutation occurs before full parse/capability validation, conflict
  analysis, both choices, projected reference analysis, final confirmation,
  and transaction-start fingerprint revalidation.
- Same-source divergence follows the selected workout mode. Numeric source IDs
  are mapping keys only. Parent-linked smash rows follow replaced workouts;
  independent same-date smash rows remain.
- Current workout/program references keep target-only custom and
  catalogue-missing identities physically available. Programs, profile, daily
  metrics, check-ins, and other domains retain their prior non-selectable
  semantics.
- Every current `app_meta` key and the unknown-key fallback are classified as
  target-local infrastructure; source lineage and reconciliation state are not
  restored from a backup.

## User-facing boundaries

All new restore text is an Android string resource. Final confirmation
discloses metadata reset, reference retention, custom definition replacement,
same-source divergence, and out-of-scope preservation. Internal parser and
transaction messages are not rendered directly. A stale transaction-start
fingerprint uses `RESTORE_PREFLIGHT_STALE`; malformed and stale failures map to
separate localized messages.

## Version and compatibility

- App: 0.5.0.24 / 500024 -> 0.5.0.25 / 500025
- Room: 28 -> 29
- Backup format: 11 -> 12
- Restore schema: 10 -> 11
- Formats 11 and supported pre-manifest backups remain readable through the
  compatibility path. They never synthesize explicit format-12 override
  authority.

## Invariants and rollback

No analysis formula, ProgramBuilder policy, canonical exercise stableKey, or
localized label is promoted into persisted semantic authority. Rollback must be
a forward migration from Room 29; do not destructively downgrade a user
database. The six unrelated dirty `outputs/*` files were preserved and excluded
from all task commits.
