# WhatYouGottaDo 0.5.0.38 Strict Bayesian Reliability Retry

## Baseline

- Baseline: `bb2c43525a5ac112fb91e2c93a107ff39baa75db` from latest `origin/main`.
- App identity remains `0.5.0.38 / 500038`; this isolated follow-up does not
  bump the version or create a tag.

## Cause

Strict Bayesian Lab v0.7 preserved typed failure codes, but most useful context
was flattened into free-form lines. A retry also reused the same deterministic
chain seed for identical prepared input. Users could not see which functional
failed or request a bounded exploratory retry after an eligible reliability
failure.

## Changes

- Added one structured `StrictFailureDiagnostics` model for Phase A, sampling,
  numerical, snapshot, stale-result, and unexpected failures.
- Stabilization now retains final-window gZ, tauDyn, lag, source-contribution,
  and response-functional R-hat observations.
- Production reliability failures retain offending R-hat, bulk/tail ESS,
  MCSE/SD, thresholds, draw counts, and lag visitation details where relevant.
- Added deterministic retry-attempt identity to chain seeds. Attempt zero is
  the first run; later attempts are different but reproducible.
- Kept the default STRICT APP_RUNTIME policy and its fingerprint unchanged.
- Added one user-requested RELAXED profile: one stabilization pass, 4,000-draw
  stabilization cap, R-hat below 1.05, ESS at least 50, and MCSE/SD at most
  0.20.
- RELAXED is offered only for convergence, lag mixing, and Monte Carlo
  precision failures and is visibly marked when successful.

## Preserved Boundaries

Weekly snapshots, Phase A ingestion/representation/row/scaling authorities,
multi-lag design materialization, likelihood, priors, group-Horseshoe
equations, tau0 calibration, observation-space kernel, Sigma/B update order,
Rao-Blackwellized lag posterior, and normal result layout are unchanged.

## Selectable RELAXED Mode And Failure Export Follow-up

- Baseline: `a792efc8438e9964593e4802728b05bcfac146fd` from latest
  `origin/main`; app identity remains `0.5.0.38 / 500038` and no tag is added.
- Added explicit analysis-level STRICT/RELAXED selection before execution.
  Generic retry preserves the current mode; eligible STRICT failures expose a
  typed relaxed escalation route.
- RELAXED may reuse the existing family semantic map for `INCONCLUSIVE`
  diagnostics only. `UNSUPPORTED`, cumulative/unknown without explicit policy,
  and positive I(0)/I(1) evidence are not relaxed.
- If existing optional/Pmax degradation cannot retain three common rows,
  RELAXED may deterministically remove user controls using CLOSED-week
  availability only. Every attempt rebuilds Phase A, scaling, grouping, tau0,
  and designs from the effective request; removed controls cannot re-enter as
  automatic candidates.
- The existing RELAXED sampler constants and every v0.7 equation remain
  unchanged. The STRICT APP_RUNTIME fingerprint remains the exact baseline
  value.
- Added structured relaxation provenance, Pmax/common-row diagnostics, actual
  failing MCMC functional attribution, persistent RELAXED result disclosure,
  and bounded SAF TXT failure export with app version and build commit SHA.
