# v0.5.0.32 canonical metadata normalization

## Baseline

- Started from latest `origin/main` at `8c9849ee49b89692fa79929aee4d7572f72a7512`.
- Previous app identity: `0.5.0.31 / 500031`.
- Baseline contracts: Room 29, backup format 12, restore schema 11, program backup 2.
- Canonical inventory: 257 identities, comprising 241 selectable identities and 16 history-only identities.

## Cause

The metadata architecture retained useful intrinsic facts such as plane, laterality, muscle and fatigue metadata, but some downstream badminton analysis still inferred sport-transfer meaning from those generic facts. The canonical movement relation `TRUNK_BRACE` also combined axial strength bracing, anti-rotation and other trunk-control demands in one overloaded bucket.

## Changes

- Reused the existing canonical workbook and multi-valued movement-relation owner; no parallel ontology, Room column or backup field was added.
- Decomposed all 11 former `TRUNK_BRACE` relations into reviewed `ANTI_ROTATION`, `ANTI_EXTENSION`, `ANTI_LATERAL_FLEXION` and `DYNAMIC_TRUNK_STABILIZATION` relations.
- Added reviewed `AXIAL_BRACING` relations to 10 loaded strength/carry identities where external-load transfer is exercise-defining.
- Kept `TRUNK_ROTATION`, `AXIAL_BRACING` and `ANTI_ROTATION` semantically distinct.
- Switched canonical badminton interpretation to explicit badminton type, target and physical-quality relations.
- Removed generic plane, laterality, muscle, fatigue and broad role/category inference as canonical badminton-transfer authority.
- Kept the previous generic interpretation isolated as historical/user-created compatibility audit behavior.
- Preserved badminton `fatigueCost` inputs and thresholds exactly.
- Regenerated canonical workbook exports, Korean/English display resources, protocol registry entries and deterministic audit artifacts.

## Existing-owner decisions

- Existing movement relations represent push/pull mechanics, plane, laterality and multi-valued trunk control.
- Existing badminton relations represent transfer level/type/target/quality and remain the only canonical sport-transfer authority.
- Existing muscle relations and fatigue/load fields remain legitimate metadata for their proper consumers.
- No new field, scalar replacement, Room owner, backup owner or `forceTypeV2` was created.
