# v0.5.0.21 release notes

## Summary

v0.5.0.21 is a behavior-preserving metadata and persistence migration. It
separates intrinsic exercise training meaning (`TrainingRole`) from
ProgramBuilder placement capability (`ProgramSlotCapability`) and removes the
mixed production `trainingRole` field.

## Baseline and cause

- Baseline `origin/main`: `cc0f156451b35c26a68edffb8b4c2df8e4421e58`.
- The legacy field mixed exercise semantics with program placement. Analysis,
  fatigue, editor, backup, and builder code could therefore depend on a value
  whose meaning changed by consumer.

## Changes

- Added typed `TrainingRole` and `ProgramSlotCapability` namespaces.
- Added versioned normalized relation assets joined by exact stableKey.
- Migrated the approved 26 legacy placement assignments mechanically with zero
  missing, additional, changed, or duplicate rows.
- Added 19 evidence-supported TrainingRole rows: STRENGTH 5, POWER 6,
  PLYOMETRIC 4, STABILITY 4.
- Left five ACCESSORY and two SPEED_REACTIVE intrinsic meanings absent and
  `REVIEW_REQUIRED`; placement capability is still preserved.
- Cut the advanced ProgramBuilder path over to ProgramSlotCapability without
  changing selection, fallback, substitution, timing, or prescription policy.
- Replaced non-program legacy derivations with the explicit metadata fields
  that already own those meanings.
- Removed `Exercise.trainingRole`, `FatigueTrainingRole`, seed/editor/display
  fields, and the seed CSV column.
- Added Room schema 27 with normalized relation tables and migration 26 -> 27.
- Added backup format 10 and restore schema 9. New backups export normalized
  role columns; old `training_role` remains import-only compatibility data.
- Registered translation-readiness entries without creating display keys from
  enum names.

## Behavior and no-change boundary

- The 26 approved ProgramBuilder placements are preserved exactly.
- No capability is manufactured for an unlisted exercise.
- TrainingRole never grants main, secondary, or accessory placement.
- ProgramSlotCapability is not consumed by OFI, fatigue, muscle,
  connective-tissue, badminton-transfer, or strength-proxy analysis.
- Exercise identities, movement/anatomy relations, strength-proxy relations,
  badminton relations, muscle/connective-tissue mappings, OFI coefficients,
  inventory size, stableKeys, and user records are unchanged.
- The public generator remains ProgramAutoBuilder. A full ProgramBuilder
  metadata and policy redesign is deferred.

## Persistence

- Room tables:
  - `exercise_training_role_relations`
  - `exercise_program_slot_capability_relations`
- Both use composite primary keys and exact stableKey foreign keys.
- Migration rebuilds the affected foreign-key graph while preserving IDs and
  rows; destructive migration is not used.
- Legacy backup codes are decomposed during import and are not retained as a
  mixed field.
