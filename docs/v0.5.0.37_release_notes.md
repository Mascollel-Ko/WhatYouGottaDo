## Product contract

Production exercise semantics now follow one path:

`explicit table/reviewed relation -> exact stableKey -> controlled parser -> typed semantics -> calculator`

Exercise names remain presentation, localization, accessibility, search, and diagnostic data. Names, descriptions, category text, stableKey fragments, movement/equipment/family resemblance, and broad tokens do not create analysis or planning semantics.

Changed outcomes are classified as `SAME_CANONICAL_RESULT`, `EXPLICIT_AUTHORITY_CUTOVER_SAME_RESULT`, `MISSING_COVERAGE_REPAIRED`, `INVALID_INFERENCE_REMOVED`, or `INTENTIONAL_FAIL_CLOSED`.

## Metadata and import

- Removed dead SeedData metadata inference and runtime planning/analysis fallbacks that derived meaning from names or related text.
- Current canonical built-ins require explicit canonical metadata. Custom/imported/unresolved identities without authority remain neutral rather than borrowing a similar built-in's semantics.
- A legacy backup exercise with a blank stableKey previously could be promoted to a current built-in by matching its name. It now receives a deterministic custom stableKey based on immutable backup identity and remains a custom exercise.
- The display name is preserved, but no canonical muscles, movement, load policy, CoreClass, badminton objective, strength proxy, tissue relation, or ProgramBuilder eligibility is granted by that name.
- Daily fatigue repeat grouping now uses exact stableKey. Renaming the same identity does not change fatigue; distinct identities sharing a name do not merge.
