# WhatYouGottaDo 0.5.1 UI/UX Refinement

## Baseline and scope

- Started from verified local and `origin/main` commit
  `a64cdd831bb54ba5619e270008612c39572bb333`.
- This release contains six independently revertable UI/presentation changes
  followed by this version-only release commit.
- Presentation/UI behavior changed. Analysis and canonical metadata semantics
  did not change.

## Changes

1. `013a337` preserves the Record calendar exercise search while editing dates,
   then performs one confirmed-entry jump and a restrained highlight only after
   an explicit matching-result tap.
2. `eb67123` keeps ordinary weighted set fields in `reps -> kg -> RPE` order
   before and after confirmation.
3. `9260a1e` adds long-press header drag reordering for daily exercise cards.
   Its dedicated transaction changes only `WorkoutEntry.displayOrder`, records
   a local manual-order marker, and does not request analysis recalculation.
4. `59c6a74` adds a compact rest-timer bar above bottom navigation. Dismissal is
   scoped to one timer run, does not stop the timer, and the original total
   duration is retained only to restore the presentation progress ratio.
5. `c6af7ba` replaces exercise illustrations with stable-key assets. It adds
   250 deterministic PNG replacements, retains six existing fallback images,
   and resolves image paths only at the exercise-detail presentation boundary.
6. `0c383f7` adds bounded two-finger vertical zoom and axis reset to persistent
   strength history charts without changing chart series or posterior values.

  order are unchanged; manual reordering writes only `displayOrder`.
- Rest timer end time, countdown, notification, sound, vibration, and stop
  behavior are unchanged.
- Chart lines, points, labels, source series, posterior estimates, and default
  auto range are unchanged until the user pinches.
- Bayesian v0.7, persistent strength estimation, fatigue, readiness, OFI,
  connective-tissue, badminton, recovery, and program calculations are

  release and introduces no new numerical or semantic authority.

## Known limitations

- `ex_eaea872c` has no approved replacement and no baseline fallback image.
- Vertical zoom is intentionally limited to persistent strength history charts
  and does not add horizontal zoom or alter chart data.
- Dragging intentionally begins only from the exercise-name header so set
  controls and normal scrolling retain their prior interaction behavior.

## Rest timer lifecycle hotfix

- Foreground-bar dismissal now uses the persisted timer end time, record date,
  entry ID, and set ID instead of the controller-local `runId`. The same timer
  therefore remains dismissed after restoration, while a new timer for the
  same target appears normally.
- This is presentation-only. Countdown timing, notifications, sound,
  vibration, workout data, analysis, and metadata behavior are unchanged.
- `RestTimerForegroundBarPolicyTest`: 7 tests passed. Full
  `:app:testDebugUnitTest`: 1,219 tests passed. `:app:assembleDebug`: passed.
