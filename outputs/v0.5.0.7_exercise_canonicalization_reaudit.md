## Backup and operation-report boundary

- Current backup format 8 writes stableKey exercise identity and program
  exercise stableKeys; it does not serialize numeric exercise identity.
- Manifest version, entity counts and content hash are emitted and validated.
  Preflight precedes destination writing; post-write validation remains wired.
- New-format restore accepts exact canonical stableKeys and builds the restore
  plan before transactional mutation.
- Old-format import alone receives `LegacyExerciseImportMapper`; it uses exact
  keys, a single exact-name row only when the source key is blank, structured
  split rejection and placeholder-drop warnings. It is not injected into
  selection, analysis, program generation or record creation.
- Data-transfer reports begin only after a non-null picker result invokes the
  operation, represent running/success/warning/failure, persist structured
  diagnostics, retain 20 records, support copy/file export, and are not part of
  the backup payload.
